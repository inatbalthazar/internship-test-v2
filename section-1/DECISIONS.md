D1: Route guard ไว้ตรงไหน
- ทางเลือกที่คิดไว้: (A)component ครอบ route (B)ใช้ loader
- เลือก: A
- เพราะ: redirect ไฟล์เดียว ใช้ซ้ำได้ทั้ง admin และ employee และตัดสินใจก่อน render A เป็น component จึงอ่านผู้ใช้จาก Context ด้วย useAuth ได้ตรงๆ และส่งข้อความแจ้งเตือนไปกับ state ได้ และ loader เกินจำเป็นสำหรับ 3 route
- ข้อเสียของ A ที่ยอมรับ: ข้อความที่ส่งผ่าน location.state ยังค้างอยู่ถ้ากด refresh หน้าปลายทาง ต้องเคลียร์ state เอง

D2: Admin และการจัดการรายการ task
- ทางเลือกที่คิดไว้: (A)mock API เป็นแหล่งข้อมูลที่เดียว แต่ละหน้าเก็บผลที่ดึงมาใน useState และหลังสร้าง Task ก็เอา Task ที่ API คืนมาต่อท้าย (B) เก็บ Task ทั้งหมดใน Context
- เลือก: A
- เพราะ: ทำตัวเหมือนต่อ backend จริง หน้าเว็บไม่แก้ข้อมูลเองโดยไม่ผ่าน API จึงเปลี่ยนเป็น fetch จริงได้โดยไม่ต้องแก้หน้า รายการอัปเดตทันทีโดยไม่ต้องรอโหลดซ้ำ และต่อท้ายเฉพาะเมื่อ API ตอบสำเร็จ หน้าจอจึงไม่แสดง Task ที่บันทึกไม่สำเร็จ
- ข้อเสียของ A ที่ยอมรับ: ข้อมูลอยู่ในหน่วยความจำ กด refresh แล้ว Task ที่สร้างไว้หายกลับเป็น mock เริ่มต้น และถ้าอนาคตมีคนอื่นแก้ข้อมูลพร้อมกัน รายการที่ต่อท้ายเองจะไม่เห็นการเปลี่ยนแปลงของคนอื่น ต้องเปลี่ยนเป็นดึงรายการใหม่ทั้งหมดหลังสร้าง หรือดึงซ้ำเป็นรอบ
